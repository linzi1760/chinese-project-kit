# 中文项目包与 FlowKit 的映射

本 Skill 提供中文项目目录、通用工作合同与结构检查，不包含 FlowKit 连接器、执行调度器或状态同步服务。
FlowKit 是可选接入目标；没有安装或接入它，也能使用本 Skill。以下说明定义待实现的适配器职责，
不声称任何目标系统已经支持本合同或这些接口。

## 一、统一项目包

| 路径 | 本 Skill 的职责 | 可供适配器使用的信息 |
| --- | --- | --- |
| `项目配置.json` | 项目身份、场景、目录角色、实际工作目录与交付清单 | 读取配置并校验目录与文件 |
| `00_项目说明/` | 项目入口、目标、使用说明 | 目录导航与项目摘要 |
| `01_需求与设计/` | 需求、设计、`工作计划.json` | 节点目标、依赖、状态与验收记录 |
| `02_资料与输入/` | 来源资料、输入索引与使用边界 | 资料引用及其使用边界 |
| `03_工作区/` | 唯一编辑源 | 配置中的实际 `work_dir` |
| `04_成果与交付/` | 导出物、版本交付包或指向编辑源的索引 | 项目配置中的 `delivery_files` |
| `05_验证与验收/` | 检查报告和验收证据 | 节点证据文件与验收结论 |
| `06_过程记录/` | 必要决策、进度与案例索引 | 已发生的动作与后续事项 |
| `99_历史归档/` | 已停用资料与历史交付 | 经授权归档的文件引用 |

已有机器档案（例如 `.flowkit/cases/<案例>/`）保持原位；中文目录只增加可读导航和派生摘要。
八个中文外层目录负责统一用户入口；
机器协议、框架要求的文件名与源码内部目录保持其技术要求，不能仅为汉化任意改名。

## 二、两种合同的边界

`01_需求与设计/工作计划.json` 是本 Skill 的通用工作合同，可用于代码、调研、文档和其他工作。
其中的节点、依赖、状态和证据须符合 `chinese-project-kit-workflow-v1`。它不是任何目标系统的原生计划；
不能改名或改版本号后直接宣称可运行。

未来适配器必须按目标系统公开支持的合同显式转换，并通过该系统的校验。
不能根据计划图、文件名或界面样式推断目标系统的执行能力。

以下为通用计划节点字段的示意，不是外部系统请求或完整模板。项目根由使用者绑定，实际工作目录从项目配置的 `work_dir` 读取：

```json
{
  "contract": "chinese-project-kit-workflow-v1",
  "goal": "实现项目要求的功能",
  "scenario": "code",
  "status": "planned",
  "nodes": [
    {
      "id": "implementation",
      "title": "实现并验证功能",
      "depends_on": [],
      "status": "planned",
      "output_files": ["04_成果与交付/使用说明.md"],
      "evidence": [],
      "acceptance_status": "pending"
    }
  ]
}
```

目录角色、工作目录和交付清单以项目配置为权威；计划保存步骤、节点产物与证据，由适配器核对两者关系。
路径采用项目内相对路径，实际项目根由使用者绑定，不在可复用 Skill 中写入私人绝对路径。

## 三、项目根与源码工作目录

项目包根与实际工作目录是不同角色。代码可能位于 `03_工作区/源码`，成果与证据仍按项目包根定位。
仅创建中文目录不会改变任何执行工具的当前目录；需要适配器按目标工具支持的方式明确配置。

未来适配器需区分使用者绑定的项目根与配置中的 `work_dir`；以下是接口需求，不是已经实现的功能：

1. 解析项目包根，再解析其内的实际工作目录，核对真实路径仍位于授权根内。
2. 明确工具的启动目录、文件访问边界和命令使用目录，遵守目标系统的权限与并发约束。
3. 以项目包根统一解析交付物与证据路径，避免从源码目录误解析 `04_成果与交付/`。
4. 将根目录、工作目录和转换后的目标计划绑定到对应版本与运行记录。

适配器实现前，可人工从项目包根执行明确指向子目录的命令；这仍需按实际工具验证，
不能宣称已经支持任意项目结构。只读检查不得为了建立布局而修改目标项目。
中文路径的工具链执行、打包和重开兼容性须按实际技术栈验证，不以文件生成或结构检查代替。

## 四、状态和证据

通用合同使用 `planned / doing / verifying / done / blocked / cancelled`。
它们表达本合同的业务进度；外部系统的进程态、复核态与交付态必须明确映射，不能仅按名称猜测。

| 通用状态 | 含义与转换要求 |
| --- | --- |
| `planned` | 已安排，尚未执行；仅生成目录、计划或架构图仍属于这一阶段 |
| `doing` | 正在产出，有实际执行依据；不能只根据动画或计划推断 |
| `verifying` | 产出正在检查或复核；进程结束不代表通过 |
| `done` | 节点验收已通过且证据有效；项目最终完成还须通过整体交付验收 |
| `blocked` | 当前无法推进，记录阻塞原因、责任和解除条件 |
| `cancelled` | 有明确取消记录；不自动等同工具故障或中断 |

证据至少能定位来源、对应节点、版本或运行及验收结论；有哈希时沿用原始哈希。
整改导致输入或产物变化时，受影响节点应重新验证，旧结论不得继续冒充新版本验收。
计划图、目录完整、模型自称完成或执行进程退出，都不能单独把节点标为 `done`。

## 五、中文索引与旧项目

中文目录中的过程、验收、交付索引属于派生视图，必须标注来源案例或记录、源运行（如有）、来源路径、
生成时间和验证状态。原机器档案继续作为运行事实来源；索引损坏或过期时从来源重建。
用户改写索引摘要不能改变原运行状态、门禁或回执，不产生第二套验收真源。

旧项目先记录“逻辑角色 → 现有实际路径”的映射，让八个目录角色在导航中统一。
未获得迁移授权时不移动、不重命名旧文件，不改历史计划、回执或已绑定路径。
新项目按统一目录创建，旧项目映射和实际迁移是不同工作。

## 六、待实现的接入与验收

适配器应明确输入、输出及支持范围：

- 输入为使用者授权的项目包根、项目配置、通用计划及允许读取的必要证据。
- 输出为目标系统支持的计划、真实结果映射与带来源的中文索引。
- 对条件分支、人工节点、并行或定时触发等能力，逐项声明目标系统是否支持，不默认为已有能力。
- 用真实执行、目录定位、状态同步、失败处理与交付重开验证接入；保留未通过与未验证项。

用户授权生成项目包不同时授权联网、发布、外发资料、改写历史机器档案或改变目标系统权限。
适配器应复用或取得适用范围内的授权。未实现并验证适配器前，只能交付目录、合同或视图，
明确说明“尚未接入 FlowKit”，不得把设计方案写成接入完成或任务执行完成。
